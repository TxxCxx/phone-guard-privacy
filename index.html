Phone Guard Privacy Policy

Phone Guard is an on-device anti-theft utility. The current version processes protection information locally and does not transmit app-processed data to the developer or third-party servers.

English

1. Scope and summary

This policy applies to the Phone Guard Android application. Phone Guard locally processes sensor information, device state, and user settings to provide pocket protection, stationary pickup protection, device compatibility checks, alarms, notifications, and limited on-device event history.

Current-version summary: The app has no Internet permission and includes no advertising, analytics, crash-reporting, cloud-sync, or third-party data-collection SDK.

2. Information processed on the device

  • Sensor information: proximity state and supported motion-sensor information, such as linear acceleration and gyroscope events, used to operate the protection mode selected by the user and to check device compatibility.
  • Device and system state: screen and lock state, availability of a secure device lock, sensor names and capabilities, Android build fingerprint, notification and background-execution status, battery-optimization status, alarm volume and vibration availability, and rotation settings.
  • App preferences: selected language, protection mode, alarm delay, alarm duration, and related settings.
  • Protection runtime information: whether protection has started or armed, limited recent sensor evidence needed for the active session, relevant times, detected-risk reason, delivery status, alarm result, and necessary diagnostic state.
  • On-device history: up to 20 recent summaries of armed protection sessions, including protection type, relevant times, risk reason, alarm result, and end reason. The app does not create a continuous raw-sensor archive.
  • Authentication result: when owner verification is required, Android presents the system authentication interface. The app receives only success, cancellation, or failure. It does not read or store fingerprints, facial templates, PINs, patterns, or passwords.

3. How this information is used

The information above is used only to operate protection explicitly started by the user, determine protection status, start and stop alarms, display notifications, check device compatibility, save preferences, restore current runtime state, and show a limited local event history.

4. Permissions and system access

  • Notifications: to show protection status, risk, and alarm notices. Depending on the user's Android notification settings, this status may be visible in the notification shade or on the lock screen. The app does not read notifications from other apps.
  • Foreground services and wake lock: to continue protection explicitly started by the user when the app is not visible or the screen is off, while showing a persistent notification, and to process time-limited events reliably.
  • Battery optimization access: the app may open Android's system page so the user can choose whether to reduce operating-system interruptions. The app does not grant this exception itself.
  • Vibration: to vibrate during an alarm when supported.
  • System authentication: to verify the device owner before ending certain protection sessions. Authentication data remains managed by Android.
  • Modify system settings: only after the user separately grants Android's special access, and only when the user taps the in-app action to restore portrait rotation lock. The app cannot bypass the Android authorization screen.
  • Device sensors: to process proximity and motion information for the user-selected protection mode.

5. Local storage, retention, and deletion

App data is stored in Android app-private storage. Cloud backup and device-to-device transfer of app data are disabled. Raw sensor streams are processed for the active protection session; only limited runtime state and event summaries are retained.

  • On-device protection history is limited to the 20 most recent records and can be cleared at any time from the app's History screen.
  • Preferences, compatibility results, and necessary runtime state remain until they are overwritten, the user clears the app's data in Android settings, or the app is uninstalled.
  • Clearing app data or uninstalling the app removes all information stored locally by the app. The current version has no user account and no server-side user data for the developer to delete.

6. Transmission, sale, and sharing

The current app does not transmit app-processed personal data to developer-operated or third-party servers. It does not sell personal data and does not share app-processed data with advertisers, analytics providers, or data brokers.

7. Platform and website providers

Google Play and the Android operating system may independently process information related to app distribution, installation, device security, and other platform services under their own policies. Such processing is outside this app's control.

This privacy-policy website is hosted by GitHub Pages. GitHub may process technical web request information, such as IP addresses and access logs, under the GitHub General Privacy Statement. The Phone Guard app itself does not send users to this page automatically and does not receive GitHub's website logs.

8. Children's privacy

Phone Guard is not specifically directed to children and does not intentionally ask users to submit personal information.

9. Security

Data exposure is reduced through on-device processing, Android app-private storage, bounded history, and disabled backups. No security measure can guarantee absolute security.

10. Changes and contact

If the app's data practices change materially, this policy will be updated with a new effective date. Questions about this policy may be sent to hf19880808@gmail.com.

中文

1. 适用范围与摘要

本政策适用于“手机防盗守护”Android 应用。应用会在用户设备本地处理传感器信息、设备状态和用户设置， 用于提供离袋守护、静置防拿、设备兼容性检查、报警、通知和有限的本机事件历史。

当前版本摘要：应用没有互联网权限，也没有集成广告、分析、崩溃上报、云同步或第三方数据采集 SDK。

2. 应用在设备上处理的信息

  • 传感器信息：接近状态以及设备支持的运动传感器信息，例如线性加速度和陀螺仪事件， 用于运行用户选择的守护模式和检查设备兼容性。
  • 设备与系统状态：屏幕与锁定状态、是否设置安全锁屏、传感器名称和能力、Android 系统构建标识、 通知与后台运行状态、电池优化状态、报警音量与振动能力，以及系统旋转设置状态。
  • 应用设置：选择的语言、守护模式、报警延迟、报警持续时间及相关设置。
  • 守护运行信息：守护是否启动或武装、当前会话需要的有限近期传感器证据、相关时间、 检测到风险的原因、事件交付状态、报警结果和必要的运行诊断状态。
  • 本机历史：最多保存最近 20 条已武装守护的事件摘要，包括守护类型、相关时间、风险原因、 报警结果和结束原因。应用不会建立连续的原始传感器档案。
  • 身份验证结果：需要确认主人身份时，由 Android 显示系统身份验证界面。应用只接收认证成功、 取消或失败结果，不读取或保存指纹、面部模板、PIN、图案或密码。

3. 信息用途

上述信息仅用于运行用户主动开启的防盗守护、判断守护状态、启动和停止报警、显示通知、检查设备兼容性、 保存用户设置、恢复当前运行状态，以及向用户显示有限的本机事件历史。

4. 权限与系统访问

  • 通知：显示守护运行状态、风险和报警通知；根据用户的 Android 通知设置， 这些状态可能显示在通知栏或锁屏上。应用不会读取其他应用的通知。
  • 前台服务与唤醒锁：在应用不可见或屏幕关闭时继续运行用户主动开启的守护，并显示持续通知； 在必要的有限时间内可靠处理事件。
  • 电池优化访问：应用可以打开 Android 系统页面，由用户自行决定是否减少操作系统对守护运行的中断； 应用不能自行授予该例外。
  • 振动：在设备支持时用于报警期间振动。
  • 系统身份验证：用于在结束特定守护会话前确认设备主人；认证数据始终由 Android 管理。
  • 修改系统设置：仅在用户另行授予 Android 特殊访问权限后，并且仅在用户点击应用内“一键恢复竖屏锁定”时， 修改自动旋转和默认方向；应用无法绕过 Android 授权页面。
  • 设备传感器：处理接近与运动信息，以实现用户选择的守护模式。

5. 本地存储、保存期限与删除

应用数据保存在 Android 应用专用存储中，并已禁用应用数据的云备份和设备间迁移。原始传感器流用于当前守护会话的本地处理； 仅有限的运行状态和事件摘要会被保留。

  • 本机守护历史最多保留最近 20 条，用户可随时在应用的“历史记录”页面清除。
  • 应用设置、设备兼容性结果和必要运行状态会保留到被新状态覆盖、用户清除应用数据或卸载应用。
  • 清除应用数据或卸载应用会删除应用保存在本机的全部信息。当前版本没有用户账户，也没有开发者服务器上的用户数据可供删除。

6. 传输、出售与共享

当前应用不会把应用处理的个人数据传输给开发者服务器或第三方服务器，不出售个人数据， 也不会与广告商、分析服务商或数据经纪商共享应用处理的数据。

7. 平台与网页托管服务

Google Play 和 Android 操作系统可能根据其各自政策，独立处理与应用分发、安装、设备安全及其他平台服务有关的信息； 这些处理不受本应用控制。

本隐私政策网页由 GitHub Pages 托管。GitHub 可能依据 GitHub 一般隐私声明 处理 IP 地址、访问日志等网页请求技术信息。手机防盗守护 App 不会自动把用户发送到本页面，也不会接收 GitHub 的网页访问日志。

8. 儿童隐私

本应用并非专门面向儿童设计，也不会有意要求用户提交个人资料。

9. 安全

我们通过设备本地处理、Android 应用隔离存储、限制历史条数以及禁用备份来减少数据暴露。 任何安全措施都无法保证绝对安全。

10. 政策变更与联系

如果应用的数据处理方式发生重大变化，本政策会更新生效日期。有关本政策的问题，请联系 hf19880808@gmail.com。
